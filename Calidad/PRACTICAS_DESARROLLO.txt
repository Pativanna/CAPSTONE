                    2. PATRÓN DE CARGA TURBO
================================================================================

REGLA: Todo script de página debe seguir este patrón (ver part-list.js):

┌─────────────────────────────────────────────────────────────────────────────┐
│ (function() {                                                               │
│   'use strict';                                                             │
│                                                                             │
│   let initialized = false;  // EVITAR DOBLE INICIALIZACIÓN                  │
│                                                                             │
│   function onReady(callback) {                                              │
│     const fire = () => {                                                    │
│       if (!document.getElementById('miContainer')) return;  // VERIFICAR    │
│       callback();                                                           │
│     };                                                                      │
│     if (document.readyState === 'loading') {                                │
│       document.addEventListener('DOMContentLoaded', fire, { once: true });  │
│     } else {                                                                │
│       fire();                                                               │
│     }                                                                       │
│     document.addEventListener('page:ready', fire);                          │
│     document.addEventListener('turbo:load', fire);                          │
│     document.addEventListener('turbo:render', fire);                        │
│     document.addEventListener('turbo:frame-load', fire);                    │
│   }                                                                         │
│                                                                             │
│   function init() {                                                         │
│     if (initialized) return;                                                │
│     initialized = true;                                                     │
│     // ... código de inicialización                                         │
│   }                                                                         │
│                                                                             │
│   function cleanup() {                                                      │
│     initialized = false;                                                    │
│     // ... limpiar listeners, timers, etc.                                  │
│   }                                                                         │
│                                                                             │
│   onReady(init);                                                            │
│   document.addEventListener('turbo:before-render', cleanup);                │
│   document.addEventListener('turbo:before-cache', cleanup);                 │
│ })();                                                                       │
└─────────────────────────────────────────────────────────────────────────────┘

UBICACIÓN DEL SCRIPT EN TEMPLATE:
  - DENTRO del turbo-frame, NO en extra_scripts
  - Con atributos: defer, data-page-script, data-turbo-track="reload"

Ejemplo correcto:
┌─────────────────────────────────────────────────────────────────────────────┐
│ {% block content %}                                                         │
│ <turbo-frame id="app-frame">                                                │
│   <!-- contenido -->                                                        │
│ <script src="{% static 'parts/js/mi-script.js' %}"                          │
│         defer                                                               │
│         nonce="{{ csp_nonce|default:'' }}"                                  │
│         data-page-script="parts:mi-pagina"                                  │
│         data-turbo-track="reload"></script>                                 │
│ </turbo-frame>                                                              │
│ {% endblock %}                                                              │
└─────────────────────────────────────────────────────────────────────────────┘

================================================================================
                  2.1 FORMULARIOS EN TURBO FRAMES (CRÍTICO)
================================================================================

PROBLEMA:
  Cuando Turbo carga contenido en un frame vía fetch, los formularios con
  action="" resuelven la URL relativa a la PÁGINA PRINCIPAL, no a la URL
  del contenido cargado en el frame.

  Ejemplo del problema:
    - Usuario está en /autos/ (página principal)
    - Hace clic en "Eliminar" que carga /autos/delete/12/ en el frame
    - El form tiene action="" 
    - Al enviar, POST va a /autos/ en lugar de /autos/delete/12/
    - ¡La eliminación no funciona!

REGLA FUNDAMENTAL:
┌─────────────────────────────────────────────────────────────────────────────┐
│     SIEMPRE PASAR action_url EXPLÍCITA DESDE LA VISTA AL TEMPLATE           │
│                                                                             │
│   Vista (views.py):                                                         │
│   return render(request, 'parts/mi_template.html', {                        │
│       'object': obj,                                                        │
│       'action_url': reverse('parts:mi_accion', args=[pk]),  # ← OBLIGATORIO │
│       'cancel_url': reverse('parts:mi_lista'),                              │
│   })                                                                        │
│                                                                             │
│   Template (mi_template.html):                                              │
│   <form method="post"                                                       │
│         action="{{ action_url }}"           <!-- ← USAR action_url -->      │
│         data-turbo-frame="app-frame">                                       │
│       {% csrf_token %}                                                      │
│       ...                                                                   │
│   </form>                                                                   │
└─────────────────────────────────────────────────────────────────────────────┘

VISTAS QUE NECESITAN action_url:
  ✅ Todas las vistas de DELETE (confirm_delete.html)
  ✅ Todas las vistas de CREATE/EDIT que se cargan en frames
  ✅ Cualquier form que se muestre dentro de un turbo-frame

ARCHIVOS DE REFERENCIA (implementación correcta):
  - parts/views.py: auto_delete, workshop_delete, part_delete
  - parts/templates/parts/confirm_delete.html

                    3. PLUGINS NATIVOS (CAPACITOR)
================================================================================

CREAR UN PLUGIN:

1. Archivo Java: android/app/src/main/java/com/carinventory/app/MiPlugin.java
   - Usar anotaciones @CapacitorPlugin, @PluginMethod, @PermissionCallback
   - NO sobrescribir métodos de Plugin con visibilidad más restrictiva
   - Usar nombres únicos para métodos privados (ej: checkCameraPermission, NO hasRequiredPermissions)

2. Registrar en MainActivity.java:
   registerPlugin(MiPlugin.class);  // ANTES de super.onCreate()

3. Dependencias en android/app/build.gradle:
   implementation 'com.example:libreria:version'

4. Permisos en AndroidManifest.xml si aplica

5. Bridge JS en parts/static/parts/js/capacitor-remote-bridge.js
   O usar window.Capacitor.Plugins.MiPlugin directamente

                  3.1 PERMISOS EN ANDROID (CRÍTICO)
================================================================================

PATRÓN DE PERMISOS:

Para que getUserMedia (micrófono/cámara) funcione en el WebView de Android,
se necesitan DOS niveles de permisos:

1. PERMISO ANDROID (en el sistema operativo):
   - Declarado en AndroidManifest.xml
   - Solicitado vía Plugin de Capacitor o ActivityResultLauncher

2. PERMISO WEBVIEW (en el contenedor del HTML):
   - El WebView pregunta al usuario cuando JS llama getUserMedia()
   - Requiere WebChromeClient con onPermissionRequest()

PLUGINS DE PERMISOS DISPONIBLES:

┌─────────────────────────────────────────────────────────────────────────────┐
│ CÁMARA (MLKitScannerPlugin):                                                │
│   - Usado para escaneo de códigos de barras                                 │
│   - AndroidManifest: <uses-permission android:name="android.permission.CAMERA"/>
│   - Uso:                                                                    │
│     const { MLKitScanner } = Capacitor.Plugins;                             │
│     const result = await MLKitScanner.startScan();                          │
│                                                                             │
│ MICRÓFONO (MicrophonePlugin):                                               │
│   - Usado para grabación de voz/WebRTC                                      │
│   - AndroidManifest: <uses-permission android:name="android.permission.RECORD_AUDIO"/>
│   - Uso:                                                                    │
│     // Opción 1: Vía plugin                                                 │
│     const { MicrophonePlugin } = Capacitor.Plugins;                         │
│     const result = await MicrophonePlugin.requestPermission();              │
│     if (result.granted) { /* usar getUserMedia */ }                         │
│                                                                             │
│     // Opción 2: Vía helper global                                          │
│     if (await window.requestMicrophonePermission()) {                       │
│       const stream = await navigator.mediaDevices.getUserMedia({audio: true});
│     }                                                                       │
└─────────────────────────────────────────────────────────────────────────────┘

WEBCHROMECLIENT (MainActivity.java):
  - Intercepta solicitudes de permisos desde JavaScript
  - Verifica permisos Android y los solicita si es necesario
  - Otorga o deniega el permiso al WebView

ARCHIVOS CLAVE:
  - android/app/src/main/AndroidManifest.xml (declaración de permisos)
  - android/app/src/main/java/.../MainActivity.java (WebChromeClient)
  - android/app/src/main/java/.../MicrophonePlugin.java
  - android/app/src/main/java/.../MLKitScannerPlugin.java
  - parts/static/parts/js/capacitor-remote-bridge.js (helpers JS)

                    7. CSP + TURBO (CRÍTICO)
================================================================================

PROBLEMA:
  Turbo hace navegación SPA: carga HTML nuevo vía fetch y lo inyecta en el DOM.
  Cada respuesta HTTP tiene un NONCE diferente en CSP.
  Cuando Turbo inyecta el nuevo HTML, el navegador usa el CSP de la página
  ORIGINAL, no el del nuevo contenido.
  
  Resultado: Scripts inline con nonce del nuevo contenido son BLOQUEADOS.

REGLA FUNDAMENTAL:
┌─────────────────────────────────────────────────────────────────────────────┐
│              NUNCA USAR SCRIPTS INLINE EN TEMPLATES                         │
│                                                                             │
│   ❌ INCORRECTO:                                                            │
│   <script nonce="{{ csp_nonce }}">                                          │
│     // código inline                                                        │
│   </script>                                                                 │
│                                                                             │
│   ✅ CORRECTO:                                                              │
│   <script src="{% static 'parts/js/mi-script.js' %}"                        │
│           nonce="{{ csp_nonce }}"                                           │
│           defer></script>                                                   │
└─────────────────────────────────────────────────────────────────────────────┘

POR QUÉ:
  - Scripts EXTERNOS con src= se identifican por su URL, no por nonce
  - El navegador permite cargar scripts de 'self' independiente del nonce
  - Scripts inline DEPENDEN del nonce, que cambia en cada request

ARCHIVOS CLAVE:
  - parts/static/parts/js/app-loading-init.js  → Reemplaza inline de loading
  - parts/static/parts/js/style-watcher.js     → Reemplaza inline de estilos
  - parts/middleware.py                         → Configuración CSP

ESTILOS INLINE:
  Los estilos inline SÍ pueden usarse si están en el middleware con su hash:
  - middleware.py tiene inline_style_hashes[] con hashes SHA256
  - Si necesitas agregar un estilo inline, calcula su hash y agrégalo

HASHES DE TURBO CONOCIDOS (ya incluidos en middleware.py):
  - sha256-slBAuFS8II/0OVyG1iq6TGX+ou4IKWv71VWltRryO34=  (estilo base)
  - sha256-qcbli+4DCLc3PNbu8bzKxrKaoXNugvRN2fsUg8ejCe4=  (estilo base)
  - sha256-ZPR/EMn2/zndixTCtRDHU6AaRXXSrBvMQiyJP1+3J7U=  (parseHTMLDocument)

HASH DE UN SCRIPT/ESTILO:
  echo "contenido del script" | openssl dgst -sha256 -binary | openssl base64
  Resultado: sha256-xxxxxx=

ERRORES RELACIONADOS:
  "Refused to execute inline script because it violates CSP..."
  → El script inline no tiene el nonce correcto
  → SOLUCIÓN: Mover a archivo externo

  "Refused to load script from 'cloudflareinsights.com'..."
  → Cloudflare inyecta scripts no permitidos
  → SOLUCIÓN: Agregar dominio a SCRIPT_CDN_SOURCES en middleware.py

================================================================================
                    8. ERRORES COMUNES Y SOLUCIONES
================================================================================

ERROR: "Unable to find plugin: XxxPlugin"
CAUSA: APK actualizada pero servidor no
SOLUCIÓN: ./aplicar_cambios.sh

ERROR: "hasRequiredPermissions() cannot override..."
CAUSA: Método privado con mismo nombre que método público de Plugin
SOLUCIÓN: Renombrar método (ej: checkCameraPermission)

ERROR: Script no se ejecuta al navegar con Turbo
CAUSA: Script en extra_scripts en lugar de dentro del turbo-frame
SOLUCIÓN: Mover script dentro del content block, usar patrón onReady()

ERROR: Doble inicialización de scripts
CAUSA: No hay guard de inicialización
SOLUCIÓN: Usar variable `initialized` y verificar antes de init()

ERROR: "Refused to execute inline script" después de navegación Turbo
CAUSA: Script inline con nonce que no coincide con CSP original
SOLUCIÓN: Mover script a archivo externo (ver sección 7)

ERROR: "PREPARANDO ESTILOS..." infinito
CAUSA: CSP bloqueó scripts críticos de la página
SOLUCIÓN: Ver sección 7, verificar que no haya scripts inline

ERROR: Form POST va a URL incorrecta en Turbo frame
CAUSA: action="" se resuelve relativo a página original, no al frame
SOLUCIÓN: Pasar action_url explícita desde la vista al template
EJEMPLO:
  Vista:  'action_url': reverse('parts:auto_delete', args=[pk])
  Template: <form action="{{ action_url }}" ...>
