                    2. ARQUITECTURA DE BÚSQUEDA
================================================================================

ANTES (v1.0):
┌─────────────────────────────────────────────────────────────────────────────┐
│ Input → forEach(6000 parts) → score calculation → sort → render            │
│ Tiempo: O(n) = 200-500ms por búsqueda                                       │
│ Problema: Bloquea UI mientras itera                                         │
└─────────────────────────────────────────────────────────────────────────────┘

DESPUÉS (v2.0):
┌─────────────────────────────────────────────────────────────────────────────┐
│ Input → debounce(150ms) → Worker(índice invertido) → render                 │
│ Tiempo: O(1) = 1-10ms por búsqueda                                          │
│ Beneficio: UI siempre responsiva a 60fps                                    │
└─────────────────────────────────────────────────────────────────────────────┘

COMPONENTES:
  1. DEBOUNCE (150ms): Evita búsquedas mientras el usuario sigue escribiendo
  2. WEB WORKER: Ejecuta búsqueda en hilo separado sin bloquear UI
  3. ÍNDICE INVERTIDO: Map<token, Set<partId>> para búsqueda O(1)
  4. INDEXEDDB: Almacenamiento asíncrono en lugar de localStorage síncrono
  5. FALLBACK: Si Worker falla, usa búsqueda local optimizada

================================================================================
                    3. ÍNDICE INVERTIDO
================================================================================

ESTRUCTURA:
  invertedIndex: Map<string, Set<number>>
    - Clave: token normalizado (sin acentos, minúsculas)
    - Valor: Set de IDs de piezas que contienen ese token
  
  barcodeIndex: Map<string, number>
    - Clave: código de barras completo
    - Valor: ID de la pieza

EJEMPLO:
  Pieza: { id: 123, name: "Volante de cuero", barcode: "VOL001" }
  
  Índice generado:
    "volante" → Set([123, ...])
    "cuero" → Set([123, ...])
    "vol" → Set([123, ...])  // n-grama
    "ola" → Set([123, ...])  // n-grama
    "ant" → Set([123, ...])  // n-grama
    "VOL001" → 123           // barcode exacto

BÚSQUEDA "volante":
  1. Normalizar: "volante"
  2. Buscar en invertedIndex: Set([123, 456, 789])
  3. Calcular scores adicionales
  4. Ordenar y retornar top N

================================================================================
                    4. OPTIMIZACIONES BACKEND
================================================================================

ANTES:
  - select_related() sin .only()
  - Iteración con for-in
  - getattr() para cada campo
  - Sin cache headers

DESPUÉS:
  - .only() para limitar campos cargados
  - .iterator(chunk_size=500) para memoria constante
  - Acceso directo a campos relacionados
  - Cache headers: max-age=120, stale-while-revalidate=60

QUERY OPTIMIZADO:
  Part.objects
    .select_related('auto', 'workshop')
    .only('id', 'name', 'availability_status', 'barcode', ...)
    .order_by('-updated_at')[:limit]
