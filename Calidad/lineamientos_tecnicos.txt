Lineamientos para mantener el stack funcionando sin romper las protecciones:

1. Turbo (Hotwire) vive embebido localmente en `parts/static/parts/vendor/turbo.es2017-umd.js`. Nunca vuelvas a usar el CDN ni pegues scripts inline: importa la copia local mediante `{% static %}` y respeta el nonce entregado por el middleware.
2. La CSP exige `style-src 'self' 'nonce-...` en estilos y sólo permite atributos inline cuando el código se genera dentro de Django. Evita escribir `style="..."` en los templates. Usa utilidades Bootstrap (`d-none`, `w-auto`, etc.) o clases nuevas dentro de los CSS estáticos (`parts/static/parts/css/*`).
3. Los estilos compartidos viven en `app-shell.css` / `design-system.css` y los módulos especializados (por ejemplo manos libres o indicador Bluetooth) deben tener su hoja dedicada en `parts/static/parts/css/`. Nunca inyectes `<style>` desde JS.
4. Si necesitas manipular el DOM desde JS, recuerda que cada `<script>` debe salir vía `{% static %}` con `nonce`. No generes scripts dinámicos ni uses `eval`.
5. Cualquier dependencia externa (icons, fuentes) debe hospedarse en `parts/static/parts/vendor/` y servirse vía `{% static %}` para que WhiteNoise pueda firmarla. No referencies CDNs nuevos sin actualizar la CSP.
6. El bundle presume que los botones y componentes del flujo manos libres cambian de estado mediante `data-state`. Respeta esas clases para que el CSS pueda aplicar animaciones.
7. Antes de introducir tecnologías nuevas (frameworks, librerías), revisa la CSP en `parts/middleware.py`. Si requiere cabeceras adicionales, documenta los cambios aquí y asegúrate de no relajar las directivas sin aprobación.
8. Los flujos de voz (manos libres y búsqueda) deben detectar el MIME soportado por `MediaRecorder` mediante `isTypeSupported`. No fuerces `audio/webm`; Safari y iOS sólo exponen `audio/mp4`, por lo que siempre guarda la grabación con el contenedor devuelto para evitar fallas en producción.
9. El verificador por cámara (`/parts/scan-verify/`) reutiliza el buscador global + micrófono y funciona únicamente con piezas que ya tengan `barcode` y fotos. Mantén el layout dividido 70/30 (video / ficha) y no inyectes librerías externas para el lector; primero usa `BarcodeDetector` nativo y sólo después evalúa empaquetar un polyfill dentro de `parts/static/parts/vendor/`.
10. Para evitar parpadeos sin estilo (FOUC), todos los CSS críticos (tipografía, navbar, layout base) deben residir en `app-shell.css` y cargarse con prioridad alta. Usa `rel="preload"` para `parts/css/app-shell.css` cuando añadas nuevos templates y verifica que `layout-init.js` tenga fallback local antes de referenciar un CDN.
11. Si necesitas nuevas hojas o scripts, agrega `data-turbo-track="reload"` y un sufijo `?v=YYYYMMDD` para que el cache de Turbo se invalide al desplegar. Esto reduce las ocasiones en que un usuario ve la UI sin estilos por servir versiones antiguas.
12. Cuando un template dependa de estilos específicos, siempre añade una clase “cascara” (`.page--xyz`). Así puedes inyectar un CSS crítico inline opcional de menos de 2 KB (permitido por CSP con nonce) sólo para garantizar estructura básica si la hoja completa tarda; cualquier regla extensa debe ir al archivo estático.
13. El buscador inteligente usa `parts_catalog_cache` + `CatalogCache` en `part-list.js` para descargar un JSON ligero a `localStorage`. Si necesitas más campos, documenta el caso y mantén el límite de 10 000 filas. Cambia la versión (`parts:catalog-cache:v1`) únicamente cuando migres el formato y recuerda que la vista debe devolver `Cache-Control: no-store` y versiones ISO8601 para que el front invalide el índice local.
14. El verificador por cámara (`scan-verify.js`) mantiene su propio índice en memoria a partir de `/parts/scan-verify/search/`. Siempre sincroniza con `credentials: 'same-origin'` para no perder la sesión y maneja errores 403 mostrando mensajes claros en la UI. Si amplías ese endpoint, respeta el límite de 400 piezas por petición y evita incluir datos sensibles (solo id, nombre, vehículo, barcode, fotos firmadas).
15. La `Permissions-Policy` está definida en `SecurityHeadersMiddleware` (usa la sintaxis estándar con `;`) y se acompaña de un `Feature-Policy` heredado para compatibilidad. Sólo `camera=(self)` y `microphone=(self)` están permitidos; si agregas iframes o subdominios que requieran hardware deberás añadirlos allí y validar con el verificador por cámara.
16. Para que las pantallas dedicadas (verificador y cámara de manos libres) respeten la altura útil en iOS/Android, usa las variables `--scanner-safe-vh` y `--photo-safe-vh`. Siempre actualízalas desde JS con `visualViewport.height` antes de fijar `position: fixed`; evita valores duros como `100vh` que ignoran las barras del navegador.
17. Todo flujo de escaneo debe exponer un modo respaldo sin cámara: deja un input y botón que comparen el código con la pieza seleccionada y registra ambos casos (match/mismatch) vía `scan_verify_log`. Esto mantiene la trazabilidad exigida por Calidad y evita que el usuario quede bloqueado si el permiso falla.
18. El overlay `#app-loading-overlay` debe permanecer mientras Bootstrap/AppShell no terminen de cargar. Si creas nuevos CSS críticos, agrégalos al watcher (`data-style-watch`) o extiende el script de `base.html` en vez de esconder el overlay manualmente; la meta es eliminar totalmente los FOUC reportados.
19. Cuando una vista dependa de scripts propios (part-list, scan-verify, reportes, formularios, etc.) esos `<script>` deben vivir dentro del mismo template, no en `block extra_scripts`, para que Turbo los entregue junto al `<turbo-frame id="app-frame">`. Nunca cierres `{% block content %}` antes de incluirlos: cualquier `<script>` que quede después del `endblock` jamás se copia al frame y la página aparece sólo con HTML pelado hasta que el usuario haga F5. Etiquétalos siempre con `data-page-script` + `data-turbo-track="reload"` para que el cache sea coherente y cumpla ISO/IEC 25010 (confiabilidad) e ISO/IEC 27001 (control de cambios).
20. A nivel de front, el shell controla el overlay y el atributo `aria-busy` de Turbo. Si agregas vistas nuevas recuerda disparar `window.__setAppLoadingProgress` y dejar las hojas/JS marcados con `data-style-watch`/`data-page-script`; así podemos cachear los assets (Cache-Control: immutable en NGINX) sin sacrificar la verificación de entrega exigida por ISO/IEC 27001 A.8 e ISO/IEC 25010 (eficiencia).
21. Versionado obligatorio: cualquier CSS o JS que se sirva desde `{% static %}` y dependa de un despliegue debe llevar sufijo `?v=YYYYMMDDx` + `data-turbo-track="reload"`. Los assets de terceros empaquetados localmente (ZXing, jsQR, Chart.js, etc.) entran en la misma regla. La mayoría de los bugs de “HTML sin estilos/JS” se debe a olvidar este sufijo, así que revísalo antes de hacer merge.
22. Cuando incrustes datos iniciales (`json_script` o bloques `<script type="application/json">`), agrega siempre el `nonce` emitido por `SecurityHeadersMiddleware`. No insertes esos scripts fuera de `{% block content %}` ni de `turbo-frame`: el verificador quedó sin datos porque `scan_verify.html` usaba `json_script` sin nonce. Toma como ejemplo la vista `scan_verify_view`, que ahora genera el payload en la vista y lo entrega listo con `nonce`.
